## 新しいリポジトリの作り方（オーナーの作業）

この作業セッションからは新しいリポジトリを作れないので、GitHub 上で空のリポジトリ（README なし）を作ってから、手元のクローンで次を実行する。

```bash
git fetch origin claude/ytfromxxx-spiral-candy-grid-api-wip-e5a9d5
git push <新しいリポジトリの URL> origin/claude/ytfromxxx-spiral-candy-grid-api-wip-e5a9d5:refs/heads/main
```

- 履歴ごと移るので、「これまでの記録」がコミットの単位で残る。
- 公開リポジトリにする場合は、先に `records/` の JSON の中身（ニックネームなど）を確かめる。
- 作ったら、このセッション（または次のセッション）にリポジトリを追加すれば、そこで続きを作れる。

## 版ごとのミニゲーム（クローンしてすぐ遊べる形）

- 置き場所：`editions/<版>/`。中身は `index.html`・`game.js`・`README.md` だけ（依存なし、`index.html` を開けば動く）。
- 最初の 1 本：`editions/white-ab/`（ホワイトアウト版 AB — サトシを探せ版 v0.1）。`file://` で開いて、3 つの場面を最後まで遊べることを確かめた（エラー 0）。
- 次：`editions/black-ab/`（ブラックアウト版 AB）。仮面のデザインを議論してから。
- 単独のリポジトリに切り出す（オーナーの作業。空のリポジトリを作ってから）：

```bash
git subtree split --prefix editions/white-ab -b white-ab
git push <新しいリポジトリの URL> white-ab:main
```

気になる点（直すときは新しいソースを足す形で。既存のページは書き換えない）：

1. **ホワイトアウト版の小さな補助の文字**：stone-400（9px）は白に対して 2.5:1 で、規則の 4.5:1 に届かない。→ ホワイトアウト版の UI を作るときに、新しい色の役（`lib/blackout.ts` の `WHITEOUT.sub` ＝ 7.63:1）を使う。
2. **`retest` の 2 つの意味**：メールアドレスの試験（ホワイトアウト版）と、診断のやり直し計測（DIAG）。版の README で「retest ＝ やり直して手触りを確かめる」と一つの意味にまとめるか、片方の名前を変えるかを決める。
3. **総合メニューのリンクの列が長い**：LAB を足すたびに伸びる。新しい版では、やることボードの「画面の地図」を入口にする案。
4. **記録が散らばっている**：localStorage の鍵が 12 種類以上。新しい版では `chartui-records/1` の形にまとめて読み書きする層を足す（今回の書き出しがその最初の形）。
5. **ドット絵や「ファミコン風」の演出**：どれもオリジナルの絵と色で作っている。既存のゲームの絵・キャラクター・ロゴは版にも入れない。
