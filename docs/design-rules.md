# デザイン規則メモ（全シミュレーション）

最終更新：2026-11-12。新しい結び目などの設計に入る前に、いまある規則を一か所にまとめたもの。規則はコードで確かめられる形で書き、確かめている場所を添える。新しいページを作るときは、まずこのメモの「共通の規則」を満たすこと。

## 1. 共通の規則（すべてのページ）

| 規則 | 数値 | 確かめている場所 |
|---|---|---|
| 点滅しない | 3 Hz を超える明滅は禁止。ゆらぎは 2.5 Hz 以下・明るさ ±8% 以内 | `lib/smokeCandle.ts`（`FLICKER_HZ`）、`lib/retroBlocks.ts` |
| 動きを減らす設定を尊重する | `prefers-reduced-motion` のときは動きを遅く・小さく | 各 LAB ページ、`app/globals.css` |
| 文字のコントラスト | 背景に対して 4.5:1 以上 | `lib/engineMenu.ts`（`checkRules`）、`lib/smokeCandle.ts`（`checkEdition`） |
| 線・図形のコントラスト | 価格線・アクセントは背景・煙に対して 3:1 以上 | `checkEdition` |
| 隣り合う色 | 色相を 90° 以上離す | `checkRules`、`checkEdition` |
| 意味の色が優先 | 速度の帯（緑・黄・赤）など意味のある色は、テーマの色より優先 | `lib/engineMenu.ts` |
| 時間は実時間で | アニメーションはフレーム数でなく経過時間で進める（`1 − e^(−dt·rate)`）。dt は 0 以上に丸める | `app/lab/knot-ladder`、`app/lab/card-slots` |
| ドリーズームは画面だけ | VR / MR の中と、動きを減らす設定のときはしない（酔いを防ぐ） | `app/lab/library/entrance` |
| 速すぎる回転は遅く見せる | 実際の回転数をそのまま描かない（例：ボールの縫い目は 40 分の 1） | `app/lab/honeycomb-punish` |
| 合成データと明記 | 実データでない価格は画面に「合成データ」と書く | 各 LAB |
| 実在の人物を描くとき | 写真や実物の表紙を使わず、自分で描いた肖像（頭・肩・イニシャル）と表紙にする | `app/lab/library/entrance` |
| 本物のメールアドレス | 行のどこかに本物のアドレスが含まれていれば（`mail: "…"` のような前置きつきでも）本物として扱い、伏せ字だけを表示する。保存・送信しない。リポジトリにも書かない | `lib/whiteout.ts`（`classify`） |
| 遊びと本物を分ける | 「量子暗号」風の遊びは、画面に「本物の暗号ではない」と書く。本物の改ざん検出は署名で行う | `lib/smokeCandle.ts`（`basisGame`）、`mesh_meta.py`（`sign_meshmeta`） |

## 2. 色の規則

- **黄金比版 ＝ 墨と藍**：色相の刻み 137.5°、彩度は 1/φ ずつ。背景 #121418、文字・価格線 白練 #f3f3f2、アクセント 朱 #eb6101。
- **大和比版 ＝ 炎と蝋**：色相の刻み 360·(1 − 1/√2) ≈ 105.4°、彩度は 1/√2 ずつ。背景 #1a100a、文字・価格線 #fff4d6、アクセント #ff5e1a。
- 色は手で並べず、`palette(edition)` の規則から作る。ページは自分の色を `checkEdition` で確かめ、結果を表で見せる。
- 対戦では、Mente 側に黄金比版、FamiDance 側に大和比版の色を使う（クリスタルベイビー対決）。
- エンジンメニューの車：主色・副色・差し色の 3 色。予測の帯は主色 30%、中央線は差し色、いまの値は白い点。

## 4. 物理と幾何の規則

- **摩擦**：2 つの系列の摩擦 ＝ (1 − 相関) / 2（0 ＝ 一緒に動く … 1 ＝ 逆に動く）。`lib/famiLink.ts`、`lib/pitIn.ts`。
- **レトログリッド A|B の摩擦**はストアの `collisionParameters.friction` に保存し、クリスタルベイビー対決の μ ＝ 0.15 ＋ 0.85 × 摩擦 に使う。
- **持ち上げ**（クリスタルベイビー）：3 本の爪が当たり、各爪の必要な力 √((F sinθ)² ＋ (mg/3)²) が μF cosθ 以下で、重心が 3 つの接点の三角形の中にあるときだけ持ち上がる。左右は鏡像にして、同じ問題にする。
- **溶ける速さ**：出来高とボラティリティ（どちらも自分の平均に対する比）で決める。`meltRate`。
- **煙の破れ**：ボラティリティが高いほど、上に行くほど破れる。`tearFrom`、`smokeMesh`。
- **投球**（ハニカムパニッシュ）：重力＋マグヌス力 a ＝ k(ω × v)。玉全体が六角形の穴に入るときだけ通る。どの面にも、少なくとも 1 本は通り抜けられる球筋がある（作るときに確かめる）。
- **同時に走る手**（プロンプトチェス）：同じ区画に着いたら両方戻る、離れた区画への着地は取らない、すれ違いは取らない、止まっている相手に着地したら取る。

## 5. 二つの流儀を尊重する（Mente × FamiDance）

| | Mente | FamiDance |
|---|---|---|
| 操作 | リモコンのボタン・キー（1 目盛りずつ） | ドラッグ＆ドロップ、ロングタップ |
| 時間 | 自分のペース | 拍（120 BPM）に合わせる。拍からのずれで強さが変わる |
| 強さ | いつも同じ（安定） | タイミング次第（拍ぴったりで最大） |
| 色 | 黄金比版（墨と藍） | 大和比版（炎と蝋） |

## 6. プロンプトの規則

- プロンプトを手や操作に変える部分は「リゾルバー」として差し替えられるようにする（`PromptResolver`）。標準は AI を使わない読み取りで、読めないときは何もしない（「駐車のまま」）。AI のリゾルバーを入れても、同じ規則（合法手だけ・あいまいなら動かない）を通す。
- 本番の制限時間は 5 分、練習は 30 秒。時間切れでも、そのとき書いてあるプロンプトで走る。

## 7. これから決めること（新しい結び目の前に）

- 新しい結び目（ヒッチ、蝶々むすび、もやい結びベンド、マルチプル・オーバーハンド・ノット）の交点の数と、ろうそく足の形との対応。
- 7 点群・3 本線の規則を、立方体のはしご（8 本・8 段）とどう両立させるか。
- 各ページの規則チェックを 1 つのテスト（例：全ページのパレットを `checkEdition` 形式で確かめる）にまとめる。

## 8. Dual・パチスロ（慎重に）— `lib/dualSlot.ts`、`/lab/dual-slot`

スロットの形を使うときは、次をすべて守る（確かめている場所：`spin`・`distribution`・`transformStats`、画面の試験では 20 回すべてでペイラインの表示が抽選結果と一致）。

| 規則 | 中身 |
|---|---|
| 払い出しがない | お金・メダル・オッズ・換金・ポイントの蓄積はなし。結果は双六の駒が進むマス数だけ |
| 結果が先、表示は後 | 3 つの停止位置を先に抽選し、リールはそれを見せるだけ。止め方の操作も、ニアミス（あと少し）の演出もしない。リールは 3 本同時に止める（最後の 1 本で引っぱらない） |
| 確率は全部公開 | 全 8 000 通りを数えた出目の確率と、7 7 7（1/2000）を画面に出す |
| 選択で得をしない | Dual のどちらを選んでも、進むマス数の平均は同じ（3.5）。変わるのはばらつきだけで、その値も出す |
| 連打させない | 1 回押すと 1 回だけ（1.6 秒）。オート機能はない |
| 休憩を組み込む | 20 回ごとに休憩のカード。続けるにはボタンを押す。「やめても大丈夫」と書く |
| 演出は控えめ | 光は 3 Hz を超えて点滅しない。何も起きていない結果を祝わない（負けを勝ちに見せない） |
